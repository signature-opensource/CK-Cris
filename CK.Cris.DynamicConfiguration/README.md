# CK.Cris.DynamicConfiguration

The dynamic configuration of an application: the values that its code can change while it runs.

## The run properties

A singleton of the App (an `ISingletonAutoService` or a real object) declares a section of the App's configuration with
`[ConfigurationSection]`; its properties that its code can change at any time are `[ConfigurationLevel( Run )]` (from
CK.Cris.Executor's `CrisExecutionHost`):

```csharp
[ConfigurationSection( "CrisExecutionHost" )]
public sealed partial class CrisExecutionHost : ICrisExecutionHost, ISingletonAutoService
{
    [ConfigurationLevel( ConfigurationLevel.Run )]
    public int ParallelRunnerCount { get => ...; set { Throw.CheckOutOfRangeArgument( value >= 1 && value <= 1000 ); ... } }
}
```

- **The declaration is a contract:** the setter is thread safe and validates (it throws on an invalid value). The value
  is a basic one (a number, a boolean, a string, an enum, a `TimeSpan`, a `Guid`); a decorated property whose type is a
  class gives access to its own decorated properties (`"Section:Options:Delay"`).
- **The owner never reads the configuration:** its value is set by the `DynamicConfigurationService`.
- **The path of a property** is its section, then its name: `CrisExecutionHost:ParallelRunnerCount`, a value of the
  App's `ckonf.json` (`"CrisExecutionHost": { "ParallelRunnerCount": 4 }`, or `Defaults:App` of the central one for
  every App), restricted by a `"$LOCK"` like any value: restricted to `Init`, it is initialized, not changed; to
  `Compile`, it is burnt.

`RunPropertyDirectory` lists them: it is generated by CK.Cris.DynamicConfiguration.Engine (typed accessors, no reflection
at run time).

## The `DynamicConfigurationService`

- **At start** (it is an `IHostedService`), the initial value of each property is resolved, then set once: a configured
  value that changed since a change was recorded wins (the latest decision), otherwise the recorded change, otherwise the
  configured value. Without any of them, the property keeps the value of its code.
- **A change** (`Configure`) compares the current value (the optimistic concurrency), converts the new one, sets it (the
  setter validates) and records it in the optional `IDynamicConfigurationStore` (CK.AppIdentity.DynamicConfiguration
  keeps it in the store of the App's root party).

## The commands

`DynamicConfigurationHandlers` handles the commands of CK.IO.DynamicConfiguration: `IConfigurePropertyCommand` (a
failure has the reason in its message: the actual value on a conflict, the error of the setter...) and
`IGetRunPropertiesQCommand` (the properties that can be changed, with their current value). They are party commands at
the Critical level; a change made while impersonating is refused.
